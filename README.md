# Lotus Docs

Локальная обработка документов и изображений в браузере. React + Vite, без сервера обработки файлов.

## Запуск

```sh
npm ci
npm run dev
```

В Windows PowerShell с ограничением исполнения скриптов используйте `npm.cmd` вместо `npm`.

```sh
npm test
npm run test:e2e
npm run build
npm run test:build
```

Для браузерных тестов нужен установленный Google Chrome. Playwright запускает его без окна; тесты проверяют ширины 360, 768 и 1440 px, основные операции и доступность через axe-core. `npm run preview` позволяет открыть production-сборку. Правила размещения статических страниц описаны ниже.

## Возможности

- Статья из DOCX: очищенный HTML с маркерами `<!-- img1 -->`, `<!-- img2 -->` и далее для Битрикса и других CMS. Изображения не вставляются в текст; они доступны отдельно в списке и папке `images` внутри архива. Номер в manifest связывает маркер с файлом. Markdown сохраняет комментарии, обычный текст — названия маркеров. Повторные и краевые переносы убираются, абзацы с изображениями разделяются с сохранением текста и ссылок. Предпросмотр только для чтения, без неочевидной браузерной «проверки орфографии».
- Сжатие: три режима JPEG/WebP — бережный, сбалансированный и сильный. По умолчанию используется сбалансированный режим с более гибким порогом сходства. PNG обрабатывается без изменения пикселей и может остаться прежнего размера. При увеличении размера, недостаточном качестве или потере прозрачности при выборе JPEG сохраняется исходный файл с правильным расширением. Желаемая экономия не гарантируется, размеры в пикселях сохраняются. Небольшая экономия показывается в байтах и долях процента, без «−0%».
- Конвертация: два файла с меню исходного и выходного формата. Тип входящего файла определяется автоматически по содержимому; выходное меню содержит только поддерживаемые направления. Изображения, DOCX → HTML/PDF, CSV → JSON, XLSX → CSV. PDF как исходник не поддерживается. Явная конвертация сохраняет выбранный выходной формат и может увеличить размер файла.
- Векторизация: растр → SVG с настройкой цветов, детализации и сглаживания.

Единая чёрно-белая тёмная тема без переключателя. Вступительная анимация с логотипом и сходящимися полосами показывается при каждой полной загрузке документа, включая новую вкладку и повторное открытие. Переходы внутри сайта её не запускают. Любое нажатие клавиши или касание пропускает заставку. При `prefers-reduced-motion` она отключена. На главной — масштабируемая SVG-композиция листов: плавное раскрытие за 4,8 секунды, затем статичное состояние. GIF и кнопки паузы нет. Движение отключается системной настройкой reduced motion.

## SEO и размещение

Скопируйте `.env.example` в `.env` и укажите реальный публичный домен в `VITE_SITE_URL` перед сборкой. Без домена сборка намеренно не выдумывает canonical и не создаёт sitemap.

`npm run build` создаёт пять полноценных HTML-страниц: главную и четыре инструмента. Каждая содержит собственные title, description, один H1, Open Graph, Twitter Card и JSON-LD WebApplication; при указанном домене также canonical, WebSite, BreadcrumbList и sitemap.xml. robots.txt генерируется при каждой сборке. Интерфейс подключается к готовому HTML через React hydration. Это соответствует [рекомендациям Google для JavaScript-сайтов](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

Хостинг должен отдавать `dist/<маршрут>/index.html` для соответствующего маршрута, а неизвестным адресам — HTTP 404. Статический sitemap и canonical используют адреса без завершающего слеша (кроме главной); настройте единую политику редиректов на хостинге. Не используйте универсальный ответ HTTP 200 для несуществующих страниц.

## Проверки и ограничения

Автоматические проверки ориентированы на [WCAG 2.2](https://www.w3.org/TR/WCAG22/): контраст, доступные имена, семантика и управление с клавиатуры. Они не являются полной сертификацией доступности; ручная проверка со скринридерами и в Safari/Firefox остаётся отдельным этапом.

Качество сжатия оценивается по выборке пикселей; оно не гарантирует визуальную идентичность. PNG может остаться без уменьшения размера. DOCX сохраняет структуру статьи, а не точную печатную вёрстку Word. Большие изображения ограничиваются доступной памятью браузера. PDF и другие тяжёлые обработчики загружаются по требованию; сборщик сообщает о размере этих отдельных пакетов.
